# 路线图

路线图按可验证阶段推进。只有当前 Phase 的 Definition of Done（DoD）全部满足后，才进入下一阶段。

## Phase 0：文档和边界

状态：**完成**

DoD：

- `AGENTS.md`、根 `README.md` 和 `docs/` 索引存在；
- v1 范围、非目标、需求和开放问题明确；
- 总体架构、规则契约、MongoDB 模型、审核和性能策略就绪；
- 进度日志记录验证证据和下一步。

## Phase 1：后端骨架和契约测试

状态：**完成（MongoDB 真实连接按用户要求延后）**

DoD：

- Python 项目、配置加载、日志、健康检查可运行；
- 领域包与适配器端口建立；
- 规则 JSON Schema 和示例有自动测试；
- 数据库初始化端口和禁用适配器可用；MongoDB 真实连接、索引和仓储契约在连接信息就绪后补齐；
- README/AGENTS 记录权威开发、测试和 lint 命令。

## Phase 2：规则归一化与基线检索

DoD：

- 能按项目和目标读取当前规则、项目上下文与上一已批准模板；
- 规则 canonicalization、hash 和结构化 diff 测试通过；
- 无基线、过期 Schema 和并发版本场景可解释。

## Phase 3：SQL 生成和静态验证

DoD：

- provider 接口和一个实现可用；
- 严格结构化候选输出可解析；
- AST 只读、白名单、参数化和条件覆盖门禁通过；
- 固定夹具测试不依赖在线模型。

## Phase 4：性能验证与临时表计划

DoD：

- 首个目标 SQL 方言 adapter 可运行 `EXPLAIN` 和取消；
- 单查询/分阶段选择有证据；
- 临时表在同一会话创建和清理；
- 超时、阶段失败和等价性测试通过。

## Phase 5：人工审核和版本发布

DoD：

- 审核 API/UI 能展示完整审核包；
- 批准、驳回、revision 和过期处理可用；
- MongoDB 原子发布、并发冲突和审计测试通过；
- 批准后哈希锁定。

## Phase 6：集成、部署和试点

DoD：

- Docker/目标环境配置、密钥管理和最小权限账号就绪；
- 指标、结构化日志和告警可用；
- 用脱敏的报告/原始数据样例完成 UAT；
- 运维手册、回滚流程和安全检查通过。

## Phase 7：后续候选

不纳入 v1，需独立 REQ：更多 SQL 方言、模型评测集、审核意见学习、批量项目迁移、正式查询调度和通用 ChatBI 能力。
