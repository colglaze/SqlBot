## 审核修复（2026-09-10 追加）

以下审核问题已修复，未进入 M2：

### 1. RepositoryVerifiedHandoffV3 构造边界
- 问题：原构造器可用 `rule_version`/`request_id`/`fact_code`/`payload` 四个普通参数直接创建 verified 类型，绕过仓储背书。`repositoryVerified` 额外参数从未被旧构造器接受。
- 修复：`__init__` 无条件 `raise TypeError`。M1 无仓储背书，所有正常构造路径均失败。
- 回归测试：7 项正常构造路径失败测试（dict 解包、JSON loads、closure 字段提取、parsed payload、dict payload、空参等）；2 项非 wire DTO/无 Pydantic 反序列化接口断言。

### 2. M1/M2 边界恢复
- 问题：`HandoffClosureV3.validate_identity_closure` 实现了跨字段身份比对（M2 范围）。
- 修复：删除该方法及其所有检查。M1 只保留 schemaVersion/strict/camelCase/extra=forbid/
  字段格式/长度/fixed intakeStatus/嵌套 payload 结构约束。
- 新增测试：`test_closure_constructs_with_mismatched_rule_version_in_m1`、
  `test_closure_constructs_with_mismatched_request_id_in_m1` 证明 M1 不比对跨字段身份。

### 3. 移除领域层重复常量
- 问题：`handoff_closure_v3.py` 重复定义 `FACT_BINDING_SCHEMA_ID_V3`/`FACT_BINDING_SCHEMA_SHA256_V3`，
  文档称"领域层可读取 application 常量"。
- 修复：删除重复定义和错误描述。测试层直接从 `application/handoff_intake_v3` 导入。
- 新增测试：`test_handoff_closure_module_does_not_import_application`。

### 4. V2 拒绝测试补实
- 问题：原测试使用缺字段临时字典，不能证明 V2 fixture 被拒绝。
- 修复：使用仓库已有完整 `fact-binding-request-2.0.0.synthetic-ready.json`，
  先证明其通过 V2 consumer，再证明 V3 closure 拒绝。

### 5. 字段边界参数化
- 新增：ruleVersion/requestId/factCode 边界、三个 SHA-256 字段的合法值/长度/大写/非十六进制。

### 6. 批准校验修正

  `approval_record.snapshotRef.snapshotVersion` 并重算自哈希，不同步修改 context。
