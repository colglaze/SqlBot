- 方案冻结要点：
  - 审核状态机 `pending → underReview → approved | rejected | revisionRequested`，
    `approved` 经独立发布门禁进入 `published` 终态；`rejected`/`revisionRequested` 为
    候选版本终态，修订只经新候选版本（新 `contentSha256`）走完整链路；
  - 候选载荷与 `reviewStatus=pending` 契约字段永不修改；有效状态由 insert-only 决策
    记录（每版本至多一个）+ insert-only 生命周期事件 + CAS 状态指针表达，模式与
    [BIZ-20260906-03](../decisions/BIZ-20260906-03-v3-downstream-authority-boundary.md)
    第 5 条冻结的 context 生命周期方案同构，不引入第二种生命周期语义；
  - 审核包 `CandidateReviewPackageV2` 不持久化：由权威输入确定性组装并重算全部闭包
    （候选自哈希、generation input、resolution/context/snapshot、静态报告引用、
    Phase 5 证据逐字段 candidateRef），决策与发布只登记其哈希；
  - 决策与发布前强制完整重算：对包内 generation request 重算 Phase 2G（复用
    `resolve_metadata_v2`）与 Phase 4（复用 `validate_sql_candidate_v2`）并 canonical
    比对，任一不一致零写入（blocked 候选同样可被 reject/requestRevision，审核对象
    包括失败候选）；
  - 发布是独立门禁动作（静态 `passed` + 有效 approve 决策从存储精确读取 + Phase 5A
    describeOnly `passed` 证据在案 + 主体边界），产出自包含发布记录（逐字节嵌入被批准
    候选载荷）；Phase 5B/5C 实施后加入强制集；发布记录不含任何运行许可字段，执行与
    调度仍属路线图"后续候选"；
  - 并发冲突由唯一索引 + 服务层先验校验裁决：同版本并发决策恰好一个生效，败者确定性
    冲突结果且零写入（冻结为不落库，开放问题可复议）；
  - 首个实施切片只提供本地 CLI（`review-export/decide/publish/status/rebuild-pointer`），
    无 HTTP 入口；HTTP 审核入口被独立认证授权设计门禁（延续 BIZ-20260905-01 第 5 节），
    CLI 不提供任何绕过门禁的参数；
  - V2/V3 隔离延伸到审核与发布层：记录携带候选契约版本与哈希闭包，V3 候选审核对齐
    依赖 [REQ-20260906-04](../requirements/REQ-20260906-04-v3-downstream-pipeline-alignment.md)
    M1–M6 完成后另立任务，此前对 V3 载荷 fail closed；
