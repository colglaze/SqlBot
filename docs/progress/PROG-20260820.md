## 仓库核对结论

- 开始时当前分支与 `origin/main` 同步，工作区无未提交修改；
- 现有事实绑定代码与 2026-08-19 的 REQ/BIZ/DEV 一致；
- 用户要求的规则 canonicalization、内容哈希和结构化 diff 只存在于已被替代的历史设计，当前代码没有实现；
- 本次将其恢复为独立的确定性规则审计能力，不恢复未经确认的整规则异常集合 SQL 职责；
- `pyproject.toml` 要求 Python 文件使用 LF，但 Windows checkout 使用 CRLF，导致权威 format check 失败；新增 `.gitattributes` 固定 Python 文件为 LF，并完成机械格式归一化。

## 已完成

- 新增与 `release-rule.schema.json` 对齐的封闭规则领域模型和领域值校验；
- canonical JSON 固定对象键顺序、UTF-8 和紧凑表示，显式保留逻辑默认值及条件数组顺序；
- 新增覆盖完整规则载荷的 `sha256:` 内容哈希；
- 新增按 `condition_id` 对齐的新增、删除、修改和逻辑结构变化 diff；
- 逻辑签名覆盖组合符、`negate`、分组、嵌套、条件顺序和路径；
- 重复 `condition_id` 通过专用异常拒绝，且返回全部排序后的重复 ID；
- 无基线显式记录 `baseline_mode=none`，不伪造哈希或空逻辑树；
- 缺少异常集合语义或真实 Schema 快照时返回结构化阻塞码；Schema 存在时继续检查字段存在性和类型；
- 领域模块不访问 MongoDB，也不导入 Web 框架、数据库驱动或模型 SDK；
- README、文档索引、路线图、REQ/BIZ/DEV 已同步。
