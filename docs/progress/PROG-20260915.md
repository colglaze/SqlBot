## 4. 真正未决项

### 元数据证据

- 所选表的精确 schema 和目标标识符大小写策略：固定资料中未找到与所选对象绑定的证据。
- 两列的完整物理类型声明与 nullable：已有粗类型不再询问，但长度/可空性缺少完整证据。
  主键候选的自动生成备注不能推导物理 `NOT NULL`；当前非空 filter 的 M3/M4 切片要求键列明确
  `nullable=false`。
- 上游实体键参数到内部主键或业务单号的精确绑定，以及与该绑定一致的唯一性/单行结果依据。
  两个字段已有含义不重复索取；`scalar` 和 field/entity-key grant 本身不证明实际只返回一行。

检索中找到的其他对象示例同名键类型已登记为排除证据，没有套用于所选表。资料中已填写的名称、
类型和业务说明直接复用，不以旧“待补充”标签否定现有内容。

### 工程登记与后续运行

正式 project/version、授权策略、元数据采集来源和时间、批准人/时间、完整哈希闭包与批准记录/指针
仍由 metadataReview 登记。这些是治理工作，不归入“用户没有提供业务资料”。后续真实生成仍需重新
读取 MongoDB、核验有效批准、重算 M2，并取得当次在线 provider 调用授权。

### 实现

- 新增 [REQ-20260915-01](../requirements/REQ-20260915-01-v3-mongodb-generation-entry.md) 和
  [DEV-20260915-01](../architecture/DEV-20260915-01-v3-mongodb-generation-entry.md)，先确定契约再实现。

  调用模型或 SQL Server。后续生成仍在同次调用中重新背书。

  候选、自哈希、证据哈希与静态结论复算一致才写出；输出冲突在模型调用前拒绝，写失败不重跑模型。

- Luna 负责领域/应用准备服务及专项测试；主 Agent 负责 CLI、导出、真实只读探测和文档。

### 真实只读核验结果

- 原本停止的 Docker Desktop 已恢复，原 MongoDB 容器启动；没有创建或替换规则库。
- 实时读取精确规则版本的 18 个请求，通过现有 intake；选定请求唯一，batch/payload SHA-256 与
  第 2 节固定导出完全一致。该次证明仅记录此次读取，不能替代生成调用中的重新背书。
- 当前 MongoDB 账号对批准记录和 active pointer 集合的 `find` 均返回 Unauthorized（13）。
  无法判定这些记录是否存在；不能把读取失败表述为“批准记录不存在”。
- 生产 SQL Server 使用当前加密配置建连时证书验证失败（08001），尚未读取表结构或业务行。
  没有降低证书校验、执行工作簿 SQL、执行候选 SQL、写生产库或写 MongoDB。
- 连接探测与最小权限草案写入公开仓库外的私有审核目录，原审核产物与清单保持不变。
  增量清单包含 8 个文件，SHA-256：
  `d01c5c18bef57ac3cf9f1004d71d8971e8065eda8aa2444dd912b6c89321ebae`。
