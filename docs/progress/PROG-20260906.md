- 领域契约 `domain/sqlserver_validation.py`：`ValidateSqlServerRequestV2`、`ValidationCaseV2`、
  `ParameterBindingV2`、`SqlServerValidationIssueV2`、`TargetEvidenceV2`、`PermissionEvidenceV2`、
  `SnapshotDriftEvidenceV2`、`DescribeEvidenceV2`、`BoundSqlRefV2`、`SqlServerValidationReportV2`；
  camelCase wire、`extra=forbid`、拒绝嵌套 snake_case、`status` 固定 `passed|blocked|inconclusive`、
  报告固定 `executable=false`、canonical `reportSha256`（排除自身哈希字段）；issue 按
  `stageOrder+code+fieldPath+safeIdentifier` 稳定排序；报告不含 SQL、参数值、连接目标、凭据、
  原始异常或业务结果；新增 `sqlserver-type-policy-v1` 类型解析/兼容矩阵。
- 端口 `application/ports/sqlserver_validation.py`（open/apply_policy/attest target/attest
  permissions/catalog facts/describe/rollback/close，driver-neutral 错误类别）与
  `application/ports/sql_parameter_binding.py`。
- 参数 binder `infrastructure/sql/sqlserver_parameter_binder.py`（`sqlserver-token-binder-v1`）：
  基于 SQLGlot tokenizer 的 COLON+VAR token span 从后向前替换；`:name` → `@pN`（describe）与
  `?`（qmark，为 5C 预留、本轮不执行）；字符串/注释/括号标识符/`::` 中的冒号不替换；重复参数
  稳定排序；记录原 SQL/派生 SQL SHA-256；无法唯一解释的占位符 fail closed。
- 配置 `config/settings.py` 与 `.env.example`：`RSB_SQLSERVER_VALIDATION_ENABLED`（默认 false，
  独立于 `RSB_DATABASE_ENABLED`）、profile ID、environment class、allowed modes（仅
  `describeOnly`）、最大并发、LOCK_TIMEOUT、describe 行/字节上限、参数 HMAC key、支持的主版本；
  启用时配置阶段硬拒绝 production（服务环境与 profile 环境）、未加密、信任服务器证书、缺失
  HMAC key（>=16 字符）、目标/凭据/profile 不完整；`safe_summary()` 只新增布尔值、profile ID、
  环境分类、允许模式和数值上限。
- 应用编排 `application/sqlserver_validation.py`：数据库访问前完整重算 Phase 2G（复用
  `resolve_metadata_v2` 经 Phase 4 服务）与 Phase 4（复用 `validate_sql_candidate_v2`，未复制规则）、
  canonical 比对携带 static report、校验 candidate 生命周期与 blocking uncertainty、profile/mode/
  requestedLimits/参数集与值策略；任何前置失败保持 adapter 调用次数为 0（测试断言）；数据库阶段
  依次 session policy → 目标身份 → 权限 → catalog 漂移 → describe，所有异常路径 rollback+close 并
  映射稳定 issue；不可用/超时 → `inconclusive`，确定性门禁失败 → `blocked`。
- ODBC adapter `infrastructure/sqlserver/odbc.py`：连接串仅由结构化字段构建（Encrypt=yes、
  TrustServerCertificate=no、ApplicationIntent=ReadOnly、Pooling=no、MARS_Connection=no、固定
  Application Name；拒绝 `;{}0x00` 值并自检未知/重复关键字）；固定 session policy 语句
  （SET NOCOUNT ON / XACT_ABORT ON / LOCK_TIMEOUT / TRANSACTION ISOLATION LEVEL READ COMMITTED）
  及 `@@LOCK_TIMEOUT` 回读；目标身份经 domain-separated HMAC 指纹比对；对象 SELECT/
  DML/DDL/CONTROL/TAKE OWNERSHIP、IMPERSONATE、db_owner/db_datawriter/sysadmin 参数化探测；
  仅对 Phase 4 实际对象做 catalog 漂移探测（alias/CLR 类型、缺列、类型/精度/空值性漂移阻断；
  额外对象/列只告警不扩大授权）；`sys.sp_describe_first_result_set` 三个参数全部驱动绑定；
  驱动错误按 SQLSTATE 映射为稳定错误类别，不透传原始文本。
- CLI `__main__.py` 改为 subparser：`serve`、`check-config`、`validate-sqlserver --input/--output
  [--mode describeOnly][--overwrite]`；不提供 `--sql/--host/--database/--username/--password`；
  开关关闭或 wire 错误退出码 4；报告独占创建、`--overwrite` 才可覆盖；stdout 仅输出 run ID、
  mode、status、issue codes、耗时和报告路径；不启动 FastAPI、不调用模型、不读私有参考 bundle。
- pyodbc 能力核对（离线证据）：`pyodbc 5.2.0` 提供 Python 3.11 wheel 并安装成功；随包
  `pyodbc.pyi` 证实 `Cursor.timeout`（查询超时秒数）、`Cursor.cancel()`、`connect(str, timeout=)`
  登录超时、`paramstyle="qmark"`、`Connection.rollback/close`。
- 文档同步：README（能力、配置表、Phase 5A 用法与安全线）、docs/README.md 索引、ROADMAP
  Phase 5 状态、REQ/BIZ/DEV 状态与实现记录、本 PROG。

  `param:v1:`）实现密钥分离；若需独立轮换可在后续任务拆分为两个 secret。
