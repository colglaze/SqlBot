### 职责边界

`_select_join_closure_v3` 沿用既有 V2 确定性连接闭包原则，返回被选中的
join grant ID（按 ID 升序排列），不表示 SQL 执行顺序。
收集所需关系 → 逐项验证 grant → 无向连通性检查 → 歧义检查。
不引入未使用的桥接关系，不自动选择生成树或最短路径。
不构造 ResolvedJoinV3，不伪造 evidenceIds，不实现公开编排。

### 算法

| # | code | 检查内容 |
|---|------|----------|
| 0 | 传播输入门禁/字段异常 | 调用输入门禁 + 字段/实体键解析 |
| 1 | 收集所需关系 | 从已解析字段物理引用收集 `(schema, relation)` |
| 2 | 传播单个 grant 异常 | 按 grantId 升序逐项调用 `_resolve_join_grant_v3` |
| 3 | 筛选候选 | 仅保留两端属于两个不同所需关系的已验证 grant |
| 4 | 连通性检查 | 无向图遍历；无法连接全部 → `JOIN_CLOSURE_DISCONNECTED` |
| 5 | 歧义检查 | 连通但候选数 ≠ 关系数-1 → `JOIN_CLOSURE_AMBIGUOUS` |
| 6 | 返回 | 候选 grant ID 升序 tuple；≤1 个所需关系返回空 tuple |

## join closure 门禁绕过修复（2026-09-11 追加）

本轮修复真实的生产缺陷，并补齐回归证据。

### 缺陷

`_select_join_closure_v3` 中，单关系提前返回（`len(required_relations) <= 1 → return ()`）位于 grant 验证之前。当请求只有一个字段所需关系、但存在引用非所需关系的额外 join grant 时，该 grant 从未被校验，直接返回 `()`。这绕过了授权门禁。

### 最小生产改动

将单关系提前返回移动到全部 grant 验证成功之后。修改仅涉及 `_select_join_closure_v3` 内部步骤顺序，不改变算法、错误码或输入契约。

### 修复前可复现行为

构造单关系请求 + 引用不存在 column grant 的额外 grant：
- 修复前：返回 `()`（grant 未验证，门禁绕过）
- 修复后：正确抛出 `COLUMN_GRANT_NOT_FOUND`

### 新增回归证据

1. **单关系 + 额外 grant 门禁**：无 grant → `()`；合法额外 grant → `()`；
   额外 grant 引用不存在 column grant → `COLUMN_GRANT_NOT_FOUND`；
   两端合法但 relationship 缺失 → `JOIN_RELATIONSHIP_NOT_FOUND`；
   relationship 重复 → `JOIN_RELATIONSHIP_AMBIGUOUS`。
2. **grant 检查顺序**：两个不同错误码的坏 grant（join-a/join-z），
   先报 `COLUMN_GRANT_NOT_FOUND`；仅修复 join-a 后报 `JOIN_RELATIONSHIP_NOT_FOUND`。
3. **字段/grant/relationship 重排**：同一合法 wire 深拷贝后重排三数组，
   输出保持一致。
4. **大小写差异**：insensitive 成功；sensitive 报 `JOIN_RELATIONSHIP_NOT_FOUND`。
