### M4 P0 缺陷修复（2026-09-13）

### 修复前已知缺陷（3 个 P0）

1. **SqlValidationIssueV3 同名冲突导致报告构造崩溃**：端口 `SqlValidationIssueV3`（dataclass）与域 `SqlValidationIssueV3`（Pydantic）同名，应用层 `issues.extend(result.issues)` 直接混入，导致任何适配器级 issue 都抛 `pydantic ValidationError` 而非返回 blocked 报告。
2. **SQL 负例测试全部空转**：所有改写 `sqlTemplate` 的 tamper 测试均未重算 `contentSha256`，触发 `CAND_HASH` 并在 parser 之前返回，16 个"blocked"断言全部空转，AST 门禁测试覆盖率为 0。
3. **首版语法黑名单遗漏**：ABS/CAST/ORDER BY/LIKE 等 SQL 在哈希自洽时全部 passed，LIKE 是未受门禁的额外谓词会静默改变结果集，CAST 会改变结果类型。

### 修复内容

**P0-1**：端口类型重命名为 `SqlInspectionIssueV3`，应用层显式转换为域侧 Pydantic issue，每个 code 赋予真实的 `gateOrder`（1/2/5/8/9）与 `fieldPath`（如 `/ast`、`/where`）。

**P0-2**：新增 `_recompute_hash` 辅助函数，在改写 `sqlTemplate` 后用 `canonical_content_sha256` 重算并回填 `contentSha256`。所有 SQL 语义/结构负例改用该辅助函数。每个负例断言具体 code 且 `report.inspection is not None`。保留独立的 `CAND_HASH` 测试断言 parser 未被调用。

**P0-3**：适配器改为白名单——SELECT 列表只允许单个裸 Column 且带 fact_value 别名，WHERE 只允许由 AND 连接的 Column = :parameter 比较。增加对函数调用（ABS/CAST/COUNT 等）、窗口函数（ROW_NUMBER/OVER）、ORDER BY、LIKE/IN/IS/BETWEEN、CASE、集合运算等的检测。WHERE 中出现任何非 EQ 比较节点类型的谓词也被计入并阻断。
