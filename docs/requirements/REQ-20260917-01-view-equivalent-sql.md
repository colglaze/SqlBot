## 目标与完成标准

当前这份模板的验收目标是 SQL 实现**优化方案**对应的完整判定（§1.3 结构 + §5.2 公式），而不是现行释放视图的 OR 支。单字段取值、CASE、rowset 或静态 passed 均不足。候选必须在已对齐的规则版本、相同数据、参数及时间基准下，与优化方案引擎预期一致，包括实体身份、结果值、空值及重复行数量。

MongoDB 精确规则版本仍驱动生成。现行视图只可用于物理关系核对，不能改写优化方案公式。Agent1 未按 [BIZ-20260917-03](../decisions/BIZ-20260917-03-optimization-plan-authority.md) 发布展开后的新 handoff 之前，不能生成该总 SQL。

“不能将整规则条件塞入单事实查询”的既有约束继续适用于单事实产物；不能再据此把单事实产物
作为本目标的最终交付。需要独立的完整规则输入及 SQL 组合能力，具体契约与设计尚未冻结。
不恢复历史整规则异常集合的默认语义，不自行推定结果是异常集合还是其补集。

## 必须逐项覆盖的语义

| 维度 | 必须核对的内容 | 当前证据与缺口 |
| --- | --- | --- |
| 结果 | 输出粒度、实体键、列、零行、多行、重复行 | 当前 V3 输出仅为一个 fact_value；rowset 不提供完整报告结果契约 |
| 取数 | 基础关系、JOIN 条件与方向、保留侧、连接倍增 | M2 有授权解析；M3/M4 仍拒绝 JOIN |
| 计算 | 金额来源、聚合范围、分组、精度及容差 | M3 拒绝聚合；M4 拒绝聚合及算术 |
| 条件 | 共同前提、AND/OR/NOT 分组、产品及合同分支 | usages 是追溯坐标，不是完整条件树；M4 禁止 OR/NOT |
| 存在性 | 存在、排除、流程状态及计数的实际范围 | M3 仅接受 source；已登记的上游计数过滤缺口仍需版本化修复 |
| 时间 | 时间字段、时区、边界包含关系、固定求值时刻 | M3 拒绝 timeRange；不能依赖模型补齐 |
| 空值 | 无匹配、匹配行 NULL、未知码及三值逻辑 | 已有 CASE 仅覆盖所选事实；不能推导最终放行结论 |
| 合并 | 合并组成员范围、成员判断与最终输出规则 | 既有记录指出来源/表达缺口，未证明完整生成能力 |

上表的业务类别来自已登记的来源分析。2026-09-17 晚已重读固定私有来源与本地 Mongo V3 handoff，
对照结论见 [PROG-20260917](../progress/PROG-20260917.md)；私有原文仍不进入本公开文件。

## 输入闭包与实施顺序

1. 复用固定来源身份与已有私有对照，建立“优化方案逻辑节点 → 精确规则条件/事实请求 → 批准绑定
   → SQL 节点 → 验收案例”的完整矩阵。缺失、冲突、无法解析的依赖必须显式列出。
2. 核对完整规则树及所有依赖事实。单个 FactBindingRequest 的 usage 坐标不能重建 AND/OR、
   NOT、阶段优先级和终止关系。上游已有表达缺口应以新规则/catalog/handoff 修复，不覆写旧版本。
3. 定义版本化完整结果契约和组合计划，绑定精确规则、全部请求、context、snapshot 与批准身份。
   当前两列测试批准不能扩大为完整查询授权；已有事实无需用户重复提供。
4. 按矩阵需要逐项实现 JOIN、聚合、存在性、时间与完整条件组合；生成器与独立 AST/语义校验
   同步扩展。不能删除现有拒绝条件后直接接受任意模型 SQL，也不能靠改变 Prompt 宣称完成。
5. 生成独立候选并完成差分验证。单事实模板继续可复用；新产物不能冒用旧候选哈希或审核结论。

## 验收证据

- 正常及边界：每个分支单独命中、多分支同时命中、前置条件失败、排除条件优先、无匹配、
  NULL、未知码、重复匹配、一对多连接、金额边界、时间边界与合并组部分成员不满足。
- 对每个案例比较实体键、全部约定输出值及重复次数；仅行数相同或 conditionId 集合相同不合格。
- 基线业务语义相同的规则版本：参考逻辑与生成 SQL 的预期结果逐项相同；规则 A/B 变化：
  只有显式变更影响结果，不能重新查询固定旧视图冒充新规则生成。
- 离线基础测试只使用合成 fixture/mock；模拟器结果不得当作 SQL Server 方言执行证明。
  SQL Server 差分验证需明确非生产目标、批准范围与受限执行条件，另行记录真实执行证据。
- 缺少规则依赖、物理授权或一致性证据时阻断相关完整查询；超时或失败不得降级为原单事实查询
  并报告成功。SQL 保持单条只读、参数绑定、不使用临时表。
- 静态安全、业务一致性、受限环境验证和人工审核分别记录状态；全部所需证据完成之前，
  本需求保持未完成，候选保持 `pending / executable=false`。
